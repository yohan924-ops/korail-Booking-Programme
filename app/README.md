# `app/` — 뉴레일 (코레일 예매 GUI)

`src/korail_mobile_api` 가 라이브러리이고, 여기는 그것을 쓰는 **프로그램**입니다.
`pip install` 에 들어가지 않습니다 — 저장소에서 바로 실행합니다.

> **씀씀이.** 이 `app/` 프로그램(뉴레일)은 개인이 직접 쓰려고 만든 것입니다.
> **무단 배포를 금지합니다** — 이 폴더나 여기서 만든 실행 파일(`NewRail.exe`
> 등)을 저자의 허락 없이 다른 사람에게 주거나 퍼뜨리지 마세요. **상업적
> 이용도 금지합니다** — 이 프로그램이나 그것으로 만든 결과를 돈을 받고
> 팔거나, 돈이 오가는 사업에 쓰지 마세요. (라이브러리 `src/korail_mobile_api`
> 자체는 저장소 위의 [LICENSE](../LICENSE)(Apache 2.0)를 따로 따릅니다 —
> 이 제한은 `app/` 프로그램에만 걸립니다.)

## 실행

저장소 맨 위의 실행기를 **더블클릭**하면 됩니다.

| 무엇을 쓰나 | 무엇을 누르나 |
| --- | --- |
| Windows | `실행 (Windows).bat` |
| macOS | `실행 (macOS_Linux).command` (처음 한 번은 오른쪽 클릭 → 열기) |
| Linux | 같은 파일. 속성에서 "실행 가능"을 켜거나 터미널에서 `./"실행 (macOS_Linux).command"` |

처음 한 번만 1~2분 걸립니다. 실행기가 하는 일은 셋뿐입니다 — 파이썬을 찾고,
**이 폴더 안에** `.venv` 를 만들어 `httpx` 와 `cryptography` 를 넣고,
`app/main.py` 를 띄웁니다. 컴퓨터에 이미 있는 파이썬 환경은 건드리지 않고,
지우고 싶으면 `.venv` 폴더만 지우면 됩니다. 두 번째부터는 바로 창이 뜹니다.
Windows 에서는 `pystray`·`pillow` 도 함께 넣습니다 — 작업 표시줄 트레이
아이콘(창을 닫아도 자동예매가 백그라운드에서 계속되는 기능)에 씁니다.
이 둘은 **있어도 그만 없어도 그만**입니다 — 못 받아도 실행기는 멈추지
않고, 창을 닫으면 지금까지처럼 곧장 끝나는 것으로 돌아갈 뿐입니다.

파이썬이 아예 없으면 실행기가 **어디서 받는지 알려 주고 멈춥니다.**
Windows 설치 화면에서 `Add python.exe to PATH` 와 `tcl/tk and IDLE` 을 둘 다
켜야 합니다 — 뒤엣것이 없으면 창이 뜨지 않습니다. 리눅스에서
`No module named 'tkinter'` 가 나오면 `sudo apt install python3-tk` 입니다.

터미널에서 직접 돌려도 됩니다:

```bash
python3 app/main.py     # httpx, cryptography 가 이미 있을 때
```

### 파이썬 없이 쓰게 하려면 (실행 파일 하나)

파이썬 설치조차 시키고 싶지 않은 사람에게 줄 때는 Windows 실행 파일을
만듭니다. **실행 파일은 만드는 컴퓨터의 운영체제 것으로 나옵니다** — 리눅스나
macOS 에서 Windows 용을 대신 만들어 줄 수 없습니다. 그래서 길이 둘입니다.

**Windows 를 쓰신다면 — `exe 만들기 (Windows).bat` 더블클릭.** 먼저
`실행 (Windows).bat` 을 한 번 눌러 `.venv` 가 있어야 하고, 그 환경을 그대로
씁니다. 1~3분 뒤 `dist\NewRail.exe` 가 나옵니다.

**Windows 가 없다면 — GitHub Actions.** Actions 탭 → **Desktop build** →
*Run workflow*. 끝나면 그 실행 기록에 `NewRail-windows` 아티팩트가
붙습니다. 단, `workflow_dispatch` 는 **워크플로 파일이 기본 브랜치에 있어야**
단추가 보입니다 — 이 파일이 `main` 에 들어간 뒤에야 쓸 수 있습니다. 두 길은
같은 PyInstaller 명령을 씁니다(시험이 둘을 대조합니다).

**아이콘을 바꾸려면** `packaging/icon.png` 에 그림을 넣어 두면 됩니다(정사각형
PNG 면 충분합니다). `.ico` 를 넣으면 그것을 먼저 씁니다. 없으면 PyInstaller
기본 아이콘으로 나오고, 없다고 빌드가 멈추지는 않습니다. CI 로 만들 때는 그
파일이 **커밋돼 있어야** 러너가 봅니다. 남의 그림을 쓸 때는 배포 범위를
생각하세요 — 개인적으로 쓰는 것과 공개해 나눠 주는 것은 다릅니다.

만든 exe 는 저장소도 파이썬도 없는 컴퓨터에서 더블클릭으로 돕니다. 설정은
`%APPDATA%\korail-booker\settings.json` 에 저장되므로 폴더를 함께 줄 필요도
없습니다. 알아 둘 것 셋:

- `--onefile` 이라 **첫 실행 때 몇 초 멈춥니다**(임시 폴더에 푸는 시간). 고장이
  아닙니다.
- **서명이 없어 SmartScreen 경고가 뜹니다**("Windows의 PC 보호"). [추가 정보] →
  [실행]. 서명을 붙이려면 코드 서명 인증서가 필요하고, 이 저장소에는 없습니다.
- **백신이 잡을 수 있습니다.** PyInstaller `--onefile` 산출물에 흔한 오탐입니다.

**이 저장소의 누구도 그 exe 가 실제로 창을 띄우는 것을 확인한 적이 없습니다** —
여기서는 만들 수도 실행할 수도 없습니다. 처음 만드는 사람이 확인해 주세요.

## 화면

1. **로그인** — 켜자마자 **로그인 팝업**이 먼저 뜹니다. 떠 있는 동안 본 창은
   눌리지 않습니다(뒤에서 조회를 눌러 놓고 로그인 창을 찾는 일이 없게).
   아이디·휴대폰번호·회원번호 중 아무거나 됩니다 — 무엇인지는 라이브러리가
   값의 모양을 보고 고릅니다(`infer_login_input_flag`). **휴대폰번호는
   하이픈(-) 없이 숫자만** 넣으라고 팝업에 적혀 있습니다.

   **[비로그인]** 을 누르거나 창을 닫으면 로그인 없이 그냥 씁니다. 열차
   조회는 다 되고 **예약과 결제는 막힙니다**(자동예매도 [바로 예약] 도
   로그인을 요구합니다) — 팝업에도 이 제약을 그대로 적어 둡니다. 로그인에
   실패하면 창은 닫히지 않습니다 — 다시 칠 수 있어야 하니까요.

   **자동예매가 도는 중에는 로그인 팝업 자체가 열리지 않습니다** — [로그인]/
   [다른 아이디로 로그인] 을 눌러도 경고만 뜨고 막힙니다. 감시가 예매 대상과
   잡은 예약 목록을 쓰고 있는데, 그 밑에서 계정이 바뀌면 감시가 다음에 무엇을
   예약하는지 알 수 없게 되기 때문입니다([중지] 를 먼저 눌러야 합니다).

   본 화면의 1번 줄에는 **상태와 단추만** 있습니다. 비밀번호 칸은 팝업에만
   있고, 창이 닫히면 값도 사라집니다.

   | 지금 상태 | 보이는 단추 |
   | --- | --- |
   | 비로그인 | [로그인] |
   | 로그인됨 | [다른 아이디로 로그인] · [로그아웃] |

   상태는 색으로도 말합니다 — **로그인됨은 초록**(아이디를 함께 적습니다),
   실패는 빨강, 비로그인은 회색. [로그아웃] 은 이 프로그램의 세션과 자격증명을
   버리고 비로그인 상태로 되돌립니다(서버로 로그아웃을 보내지는 않습니다 —
   코레일 앱의 로그인까지 끊는다고 약속하지 않습니다). 자동예매가 도는 중에는
   막습니다.

   **로그아웃·다른 아이디로 로그인·비로그인 전환, 이 셋 중 무엇이든 하면
   열차 조회 결과·예매 대상·잡은 예약 목록이 모두 비워집니다**(자동예매가
   돌지 않을 때만 — 돌고 있으면 애초에 이 전환들 자체가 막혀 있습니다).
   이전 계정이나 이전 조회의 목록이 새 세션에 남아 남의(또는 지난) 예약을
   지금 것으로 착각하는 일을 막기 위한 것입니다. 서버의 예약 자체는 지워지지
   않습니다 — 화면 목록만 비웁니다.
2. **열차 조회** — 구간·날짜·시간창(30분 단위로 고름)·열차 종류·좌석 등급
   (일반/특실/무관), 직통과 환승, 승객 5종. **환승 조건은 "환승"을 켰을
   때만** 만질 수 있고, **[조회] 는 조건 아래에 크게** 있습니다(Enter 로도 됩니다).
   - 이 묶음은 **두 칸으로 나뉩니다** — 왼쪽에 조건 줄들, 오른쪽 빈자리에 환승
     조건. 아래로 쌓으면 이 묶음만 470px 을 먹고 그만큼 열차 목록과 예매 대상이
     눌립니다. 그래서 왼쪽 줄은 좁게 유지합니다(승객과 열차 종류를 따로 줄로
     뗀 이유이고, 화면 글귀가 짧은 이유이기도 합니다).
   - **역 목록은 켜자마자 자동으로 받습니다**(로그인이 필요 없는 조회입니다).
     출발·도착 칸은 치는 대로 좁혀지고, 목록에 없는 이름을 직접 쳐 넣어도
     됩니다. 드롭다운을 스스로 펼치지는 않습니다 — 한글 입력기가 글자를
     조합하는 중에 목록을 펼치면 조합이 끊어지기 때문입니다. 아래 화살표나
     `Down` 키로 좁혀진 목록을 봅니다.
   - **날짜는 [달력] 단추**로 고릅니다. 팝업 창이 아니라 같은 창 위에 겹쳐
     뜨므로 아래 표가 밀리지 않습니다. 지난 날짜는 눌리지 않고, 칸에
     `2026-08-10` 처럼 직접 쳐 넣어도 됩니다.
   - 조회 칸은 **구간 / 가는 편 / 오는 편 / 열차 종류 / 좌석** 다섯 묶음으로
     나뉘어 있고, 각 묶음의 이름이 왼쪽에 붙습니다.
   - **왕복**을 켜면 '오는 편' 줄이 통째로 열립니다 — 오는 날짜와 **오는 편
     전용 시간창**입니다. 가는 편과 같은 시간대를 쓸 이유가 없으므로 따로
     고릅니다(예: 가는 편 08:00~11:00, 오는 편 17:00~21:00). 왕복이 아니면 그
     줄의 칸들은 잠깁니다. 조회는 두 번 돌고, 결과의 '구분' 칸에 어느 편인지
     붙습니다.
   - 열차 종류는 **체크박스를 한 줄에 늘어놓았습니다.** 여러 개를 고르면 그중
     하나라도 맞으면 통과이고, 아무것도 고르지 않으면 전부 봅니다. 거르는
     방식이 **부분일치**라 `KTX` 하나로 `KTX-산천`·`KTX-이음`까지 잡히고,
     산천만 보려면 `KTX-산천` 을 고르면 됩니다. 서버가 실제로 뭐라고 보내는지는
     결과의 '열차' 칸에 그대로 찍히니, 그 이름을 보고 고르는 것이 가장
     정확합니다. [모두 선택]·[모두 지우기] 가 옆에 있습니다 — 아무것도 안 고른
     것과 전부 고른 것은 거르는 결과가 같지만, 하나만 빼고 보려면 전부 켜고
     하나만 끄는 편이 빠릅니다.
   - **하루치를 끝까지 훑습니다.** 서버는 한 번에 열 편쯤 주고 "다음 있음"
     표시를 붙이는데, 그 표시가 없는 응답이 옵니다 — 동탄→대구(2026-09-12)에서
     13:08 출발까지만 나오고 뒤가 통째로 빠졌습니다. 그래서 표시가 없으면
     **마지막 열차의 출발 시각부터 다시 묻습니다.** 시각이 더 나아가지 않으면
     멈추므로 요청은 최대 여덟 번입니다. 왜 그 응답에 표시가 없었는지는
     확인하지 못했습니다.
   - **결과가 줄어들면 왜 줄었는지 기록에 적습니다** — 어느 조건이 몇 편을
     걸렀는지, 걸러진 열차가 무엇이었는지(종별·번호·출발 시각)까지. 오늘
     날짜로 조회하면 이미 떠난 열차는 서버가 주지 않는다는 것도 적습니다.
     기록 칸의 **[지우기]** 로 쌓인 줄을 비울 수 있습니다(화면에서만 지웁니다
     — 이 프로그램은 기록을 파일로 남기지 않습니다).
   - **아무것도 이 목록을 몰래 덮지 않습니다.** 목록은 두 모드 모두에서 사람이
     손댄 것입니다 — 직접 지정에서는 고른 역이 곧 조회 대상이고, 서버 추천에서는
     고른 역이 결과를 거르는 필터입니다.
     - **[조회]** 는 서버 후보를 함께 받아 오지만(구간이 그대로면 다시 묻지
       않습니다) 목록이 비어 있을 때만 채웁니다. 이미 무엇이든 들어 있으면
       `(검증)` 표시만 다시 그립니다.
     - **[구간 후보 갱신]** 은 **더하기만 합니다** — 있던 역은 그대로 두고,
       서버가 준 것 중 없던 것만 뒤에 붙입니다(새로 붙은 것은 선택된 채로).
       예전에는 통째로 되돌렸는데, 그것은 서버 후보에 없는 역을 넣을 수 있게
       해 놓고 후보를 한 번 더 불러오면 그 역을 지우는 일이었습니다.
     - 지우는 일은 지우는 단추가 합니다 — **[빼기]** 는 고른 역만,
       **[목록 비우기]** 는 통째로.
   - 서버도 후보로 준 역에는 목록에 **`(검증)`** 이 붙습니다. 직접 지정한 역이
     서버 추천과 겹치는지 아닌지가, 그 조합을 서버가 받아 줄 가능성을 재는
     유일한 단서입니다. 이 표시는 화면에만 붙고 조회에는 역 이름만 나갑니다.
   - **환승 조건은 환승 결과에만 걸립니다. 직통 열차는 환승역·환승시간과
     무관하게 나옵니다.** 둘은 별개의 조회이고, 한쪽이 실패해도 다른 쪽 결과는
     그대로 남습니다.
   - 환승역 목록은 [이 구간의 환승역 불러오기] 로 채웁니다. 전국 역이 아니라
     **코레일이 그 구간에 대해 답한 역**(`qry.chtnStn.do`)입니다. 그 목록이
     어떤 기준으로 만들어지는지는 코레일만 알고, 이 프로그램은 받은 그대로
     보여 줍니다.
   - 고른 역의 **뜻은 모드마다 다릅니다.** 화면의 파란 줄이 지금 어느 쪽인지
     알려 줍니다.
     - 서버 추천 환승: 고른 역은 **필터** — 서버가 준 환승 여정 중 그 역을
       지나는 것만 봅니다. 고르지 않으면 전부 봅니다.
     - 환승역 직접 지정: 고른 역이 **조회 대상** — 그 역을 경유하도록 두 구간을
       각각 조회해 붙입니다. 하나 이상 골라야 합니다.
     목록을 새로 불러오면 **전부 선택된 채**로 시작합니다. 고른 것이 화면에
     보이는 것과 실제로 쓰이는 것이 같아지기 때문입니다.
   - 직접 지정 모드에서는 **서버 후보에 없는 역도 넣을 수 있습니다.** 목록 아래
     칸에서 역 이름을 찾아 [추가] 하면 되고, 고른 역은 [빼기] 로 지웁니다
     ([구간 후보 갱신] 은 서버가 준 것으로 통째로 되돌리므로 손으로 넣은 것도
     함께 날아갑니다) — 어차피 두 구간을 따로 조회하는
     것이라 역 이름만 알면 됩니다. 서버 추천 모드에서는 그 칸이 잠깁니다(없는
     역을 넣으면 결과를 0편으로 만드는 필터가 될 뿐입니다).
   - **직접 지정의 구간 후보는 이렇게 뽑습니다** — 1구간은 `출발역→환승역`
     직통을 시간창 시작 이후로 조회해 서버가 준 순서(출발 시각순)대로 최대
     12편, 2구간은 `환승역→도착역` 을 **1구간의 가장 이른 도착 시각 이후**로
     같은 방식으로 12편. 그 조합을 환승시간으로 걸러 최대 40편까지 보여
     줍니다. 고른 **열차 종류는 자르기 전에** 걸립니다 — 거꾸로 하면 무궁화만
     보겠다고 골랐는데 앞 열두 편이 전부 KTX 라 결과가 0편이 됩니다.
   - 환승시간 기본값은 **0분 이상 30분 이하**입니다. 위쪽을 0(제한 없음)으로
     두면 몇 시간씩 기다리는 조합까지 다 딸려옵니다.
   - **직접 조합 결과는 1구간끼리 묶여 접힙니다.** 같은 1구간에 2구간만 다른
     조합이 열 개씩 나오면 표가 읽히지 않기 때문입니다. 부모 줄은 여정이 아니라
     **1구간을 알려 주는 머리글**(파란 글씨)이고, 그 아래 `└ 이어서` 줄들이
     2구간과 총 소요·환승 대기를 각각 보여 줍니다. 부모 줄을 골라 [담기] 하면
     **그 아래 조합이 전부** 담기고, 하나만 원하면 그 자식 줄을 고르면 됩니다.
     직통과 서버 추천 환승은 묶지 않습니다 — 묶어서 접을 값어치가 있는 것은
     경우의 수가 곱으로 늘어나는 직접 조합뿐입니다.
3. **열차 목록** — [결과 비우기] 로 표만 비울 수 있습니다(**예매 대상과 도는
   감시는 그대로**입니다). 직통은 한 줄, 환승은 부모 줄(총 소요·환승역·환승시간) 아래에
   구간별 줄(구간 소요)이 붙습니다. **환승은 두 구간이 한 예약(PNR)입니다** —
   한 구간이라도 매진이면 부모 줄이 `매진` 이고 담아도 잡히지 않습니다. 어느
   구간이 막혔는지는 **구간 줄의 일반실·특실 칸**에 따로 적힙니다. 자동예매는
   두 구간이 **동시에** 열릴 때까지 기다렸다가 한 번에 잡습니다 — 한쪽만
   잡아 두는 일은 없습니다(라이브러리가 한 요청으로 보냅니다).
   **왕복이면 표가 좌우로 갈립니다** — 왼쪽이
   가는 편, 오른쪽이 오는 편입니다. 나뉘면 칸이 화면보다 넓어지므로 표마다 가로
   스크롤이 붙습니다(창을 최대화하면 대부분 보입니다). 두 표에서 고른 것을 한
   번에 [담기] 할 수 있습니다.
   - 일반실·특실 칸은 앱이 화면에 찍는 문구 그대로이고(`매진`, `여유`, 운임),
     서버가 남은 좌석 수를 보내 줬으면 ` · 12석` 이 붙습니다. 환승이면 **가장
     적은 구간**의 수입니다. 서버가 안 보내면 아무것도 붙지 않습니다 — 없는
     것을 0 으로 바꾸지 않습니다.
   - **입석·자유석·대기** 칸에 그 셋이 뜹니다. 좌석이 매진이어도 이쪽은 열려
     있을 수 있습니다. 환승이면 모든 구간에 열려 있을 때만 셉니다.

     > **입석은 좌석 등급으로 고를 수 없습니다.** 라이브러리의 객실 등급은
     > 일반실(`"1"`)과 특실(`"2"`) 뿐이고, 입석 여부(`txtStndFlg`)는 고르는
     > 값이 아니라 **계산되는 값**입니다 — 일반실이면서 좌석이 매진(`"13"`)이고
     > 입석 재고가 열려 있을(`"11"`) 때 참이 됩니다. 그런데 즉시예약(`1101`)은
     > 좌석 코드가 `"11"` 일 때만 통과하므로 그 조합이 성립하지 않습니다.
     > 남은 길은 **입석+좌석 병합(`1202`)** 하나인데, 이 저장소는 그것을
     > 실서버로 보낸 적이 없어 진짜 예약에 쓰지 않습니다. 그래서 화면에는
     > **있는지 보여 주기만** 하고 고르게 하지는 않습니다.
   - 일반실·특실 칸은 **상태를 맨 앞에** 씁니다 — `매진`, `예약가능`, `-`(그
     등급 없음). 자동예매가 노리는 것이 매진이라 그 한 낱말이 먼저 와야 합니다.
     줄 색도 갈립니다(초록 = 지금 잡을 수 있음, 빨강 = 매진).
   - 표 아래 줄이 **이 표가 지금 조건의 결과인지** 말합니다. 조건을 바꾸면
     "조건이 바뀌었습니다 — [조회] 를 다시 누르세요" 로 바뀝니다. 조건을 바꿔도
     자동으로 다시 조회하지는 않습니다(체크 하나마다 요청이 나가는 편이 더
     나쁩니다). **Enter** 로도 조회됩니다.
   - 조회 중에는 [조회] 옆에 **막대가 움직이고 [조회 중지] 가 나타납니다.**
     하루치를 훑느라 요청이 여러 번 나가므로, 잘못 누른 조회를 끝까지 기다릴
     이유가 없습니다. 이미 나가 있는 요청을 도중에 끊지는 못하지만(그 답은
     어차피 옵니다) 다음 페이지를 묻지 않고, **중지한 조회의 결과는 표에 올리지
     않습니다** — 지금 조건의 것이 아닌 표가 남는 편이 더 나쁩니다. 하루치를 훑느라 몇 초
     걸리는데, 아무 표시가 없으면 눌렸는지 몰라 다시 누르게 되고 요청이 두 배로
     나갑니다. 얼마나 남았는지는 알 수 없으므로 진행률이 아니라 움직이는
     막대입니다.
4. **예매 대상과 자동예매** — 한 묶음입니다. 담는 것과 그것을 노리는 조건은
   늘 함께 쓰는데 사이에 묶음 머리가 하나 더 있으면 몸짓이 두 번 끊기고, 세로
   자리도 그만큼 먹습니다(합치면서 아래 묶음 번호가 하나씩 당겨졌습니다).
   표에서 고르고 [담기] 를 누르면 이 표에 쌓입니다. 자동예매는 **여기 담긴
   것만** 노립니다. 위 표의 선택은 조회할 때마다 사라지지만 이 표는 남습니다.
   칸은 여덟입니다. **경고는 맨 앞 상태 칸과 환승 대기 칸에 둡니다** — 여정 칸
   끝에 달았더니 표가 조금만 좁아도 잘려 보이지 않았습니다:

   | 칸 | 무엇 |
   | --- | --- |
   | 상태 | `▶ 감시 중 [A]` (초록) / `○ 대기` (회색). 구간별로 사는 것이면 `· 구간별` |
   | 여정 | 열차와 구간, 소요 시간 |
   | 환승 대기 | 조회 결과와 같은 글. 촉박하면 `⚠ … — 촉박` (빨강) |
   | 일반실 · 특실 · 입석·자유석·대기 | 조회 결과에서 보던 그대로 |
   | 조회 주기 | **그 묶음이 시작할 때 읽은** 값 |
   | 남은 감시 | 1초마다 줄어듭니다. 무제한이면 `무제한` |

   **조회 주기·감시 시간은 시작할 때 한 번 읽습니다.** 도는 중에 아래 조건 줄을
   고쳐도 이미 도는 묶음은 옛 조건으로 계속 돕니다 — 그래서 표가 그 묶음이
   실제로 쓰는 값을 보여 줍니다. 바꾸려면 줄을 고르고 **[조건 바꿔 재시작]**
   을 누르세요(멈추고, 멈춘 것을 확인한 뒤, 지금 조건으로 다시 겁니다).

   **감시 중인 열차는 뺄 수 없습니다**(빼도 그 묶음은 계속 노리므로, 목록에
   없는데 예약이 잡히면 무슨 일인지 알 수 없습니다). 먼저 멈추세요.
   같은 묶음 아래쪽이 **자동예매**입니다 — 담긴 열차를 주기적으로 다시 조회하다가
   결제 전 홀드를 만들고
   멈춥니다. **방향마다 한 건씩** 잡습니다 — 편도면 한 건, 왕복이면 가는 편과
   오는 편에 각각 한 건입니다. 같은 방향의 대상이 여럿이면 그중 먼저 열리는
   하나만 잡습니다. **시작할 때와 끝날 때 반드시 텔레그램으로 알립니다** —
   무엇을 몇 초마다 얼마 동안 지켜보는지, 그리고 왜 끝났는지(잡음·중지·시간
   끝·실패)까지. 잡았을 때만 알리면 알림이 안 오는 것이 "아직 안 잡힘" 인지
   "애초에 안 돌고 있음" 인지 구별되지 않습니다. 밤새 켜 두는 프로그램에서 그
   둘은 아주 다릅니다.
   - **담긴 것을 통째로 돌릴 필요가 없습니다.** [전체 시작]·[고른 것만 시작]·
     [전체 중지]·[고른 것만 중지] 네 단추로 나뉩니다. 묶음마다 `A`, `B`…
     꼬리표가 붙고 **자동예매 기록의 모든 줄이 그 꼬리표로 시작합니다** —
     여럿이 돌 때 어느 줄이 어느 묶음 것인지 그것으로 압니다. 같은 열차를 두
     묶음이 노리는 일은 막습니다(예약이 두 번 나갑니다).
   - **누르면 진짜 예약을 만듭니다.** 미리보기 스위치는 없앴습니다 — 켜는 것을
     잊고 미리보기를 진짜라고 믿는 일이 실제로 생겼고, 이 프로그램을 켜는
     이유가 진짜 예약이기 때문입니다. 대신 [자동예매 시작] 을 누르면 확인 창이
     한 번 뜨고, **로그인하지 않았으면 시작 자체가 막힙니다.**
   - **장바구니에 담는 기능도 없앴습니다.** 잡은 예약을 결제 기한 안에
     결제해야 하는 것은 담든 안 담든 같고, 담아서 무엇이 좋아지는지는 이
     저장소가 확인한 적이 없습니다. 확인하지 못한 것을 위해 요청을 하나 더
     내보낼 이유가 없습니다.
   - **서버가 검증하지 않은 환승 조합은 한 건으로 사지 않습니다.** 코레일이
     짝지어 준 환승(서버 추천)은 두 구간이 한 예약(PNR 하나)이지만, 환승역을
     직접 지정해 이 프로그램이 붙인 조합은 그렇지 않습니다 — 그대로 환승
     예약으로 보내면 서버가 **`ERR911193 환승최소허용시간 미달`** 로 거절하는
     일이 있습니다(실제로 받은 응답입니다). 그래서 직접 조합은 **구간마다 따로**
     삽니다. 각 구간은 그냥 직통 열차 한 편이라 보통의 예약 길이고, 서버가
     환승 조합으로 심사할 일이 없습니다.

     따로 산다는 것은 이런 뜻입니다:

     | | 서버 추천 환승 | 직접 조합 (구간별) |
     | --- | --- | --- |
     | 요청 | 한 번 | 구간 수만큼 |
     | PNR | 하나 | 구간마다 하나 |
     | 결제 | 한 번 | 구간마다 |
     | 한쪽만 잡히는 일 | 없음(한 요청이라 함께 성공하거나 함께 실패) | **있습니다** |

     한쪽만 잡히면 그 자리에서 **멈추고 크게 알립니다** — 잡힌 PNR 과 몇 구간이
     왜 실패했는지까지. 다시 시도하지 않습니다: 다음 회차에 또 돌면 이미 잡아
     둔 앞 구간을 한 번 더 잡게 되고, 그것이 중복 예약입니다. 남은 것을 어떻게
     할지(취소할지, 다른 뒤 구간을 잡을지)는 코레일 앱에서 정하세요 — **이
     프로그램은 취소를 하지 않습니다.** 예매 대상 표의 여정 칸에 `[구간별 예약]`
     이 붙고, 시작·바로 예약 확인 창에도 같은 경고가 뜹니다.
   - **환승 대기가 10분 미만이면 빨갛게** 나옵니다 — 조회 결과의 `환승 대기`
     칸과 예매 대상의 여정 칸 양쪽에서, `⚠` 표와 함께. ttk 의 표는 칸 하나만
     따로 물들일 수 없어서 색은 줄 전체에 걸립니다. 그래서 어느 칸 때문인지는
     표가 말해 줍니다.

     > **10분은 코레일의 기준이 아닙니다.** 서버가 촉박한 조합을 `ERR911193`
     > 로 거절한다는 것은 확인했지만, 그 최소 허용 시간이 몇 분인지는 알려 주는
     > 필드도, 이 저장소가 확인한 문서도 없습니다. 10분은 **이 프로그램이 눈에
     > 띄게 해 주는 선**일 뿐입니다 — 넘겼다고 예약이 된다는 뜻도, 밑돌았다고
     > 반드시 거절된다는 뜻도 아닙니다.
4-1. **바로 예약** — 이미 자리가 있는 열차는 기다릴 이유가 없습니다.
   **예매 대상에서** 고르고 [바로 예약] 을 누르면 그 자리에서 결제 전 홀드를
   만듭니다(자동예매를 걸고 기다리는 단계를 건너뜁니다).

   - **담긴 것 중에서만** 잡습니다. 조회 결과에서 바로 잡을 수 있게 두면
     "담아 둔 것만 노린다" 는 규칙이 흐려집니다.
   - **고른 것이 없으면 아무 일도 하지 않습니다.** 안 고른 것을 '전부' 로
     읽으면 실수 한 번이 여러 건의 예약이 됩니다.
   - **여럿 고를 수 있습니다.** 다만 같은 방향을 둘 이상 고르면 막습니다 —
     같은 여정을 두 번 잡는 것은 중복 예약이고 하나는 기한이 지나 버려집니다.
   - 그중 지금 못 잡는 것(만석이거나 폼을 못 만드는 행)은 **왜 못 잡는지 적고
     건너뜁니다.** 하나가 실패해도 나머지는 계속합니다.
   - 다 만석이면 "이 줄을 고른 채 [고른 것만 시작] 으로 자동예매를 거세요" 로
     안내합니다.
   - 직접 조합이 섞여 있으면 확인 창이 **[구간별 예약]** 경고를 함께 보여
     줍니다(위 참조). 앞 구간만 잡히면 그 사실과 PNR 을 창으로 알리고 잡은
     예약 목록에도 넣습니다 — 기한을 모른 채 표를 잃는 일이 없어야 합니다.
5. **잡은 예약** — 잡아 둔 예약과 **결제 기한이 1초마다 줄어듭니다.** 3분
   아래로 내려가면 빨갛게, 기한이 지나면 흐리게 바뀝니다(지웠다고 착각하지
   않도록 남깁니다). 기한은 **서버가 준 값만** 씁니다 — 주지 않으면 `기한 모름`
   이라고 적지, 10분 같은 숫자를 지어내지 않습니다. 그 값이 틀리면 표를
   잃습니다. 이 프로그램은 결제하지 않습니다.
6. **창이 가로·세로로 스크롤됩니다.** 기능이 늘면서 어떤 화면에서도 다 보이지는
   않게 됐습니다. 휠은 어디서 굴려도 듣되, 표·목록·기록 위에서는 그쪽에
   양보합니다. Shift 를 누르고 굴리면 가로입니다.

   **첫 창 크기는 안에 든 것과 화면을 둘 다 보고 정합니다** — 필요한 만큼
   잡되 화면의 92% 를 넘지 않습니다. 고정값(`1240x1000`)으로 잡아 두었더니 두
   가지가 한꺼번에 틀어졌습니다: 넓은 화면에서도 환승 조건 칸의 오른쪽이
   잘려 나갔고(가로 스크롤이 없어 잘렸다는 사실조차 보이지 않았습니다), 칸들의
   최소 높이 합이 창보다 커서 열차 표가 켜자마자 한 줄로 눌렸습니다.

   **1~5 묶음과 기록 사이에는 모두 손잡이가 있어** 서로 크기를 나눌 수
   있습니다 — 목록을 키우고 다른 것을 줄이면 됩니다. 다만 **단추가 있는 묶음은
   줄일 수 없습니다**(조회·예매 대상): 줄이면 [조회] 나 [시작] 이 잘려 쓸 수가
   없어집니다. 열차 표도 네 줄 아래로는 줄지 않습니다 — 한 줄짜리 표는 쓸모가
   없습니다. 좁은 화면에서는 줄이는 대신 스크롤하세요.
7. **기록** — 왼쪽은 로그인·조회, 오른쪽은 자동예매입니다. 한 창에 섞으면
   자동예매 회차 기록이 조회 기록을 밀어 올려 정작 볼 것이 흘러갑니다. 가운데
   손잡이를 끌어 폭을 정하고, 각각 [지우기] 로 비웁니다. 열차 목록과 예매 대상
   사이에도 같은 손잡이가 있습니다.

## 안전

| 무엇 | 어떻게 |
| --- | --- |
| 결제 | **하지 않습니다.** 결제·환불 범주의 consent 를 만드는 코드가 이 폴더에 없습니다(시험이 원문으로 확인). |
| 예약 취소 | `ui.py` **한 곳에서만** 취소 consent 를 엽니다 — 자동예매 엔진(`autobook.py`)은 절대 열지 않습니다(시험이 원문으로 확인). 잡은 예약 표에서 고르고 [선택 취소] 를 누른 뒤 확인 창에서 한 번 더 승낙해야 코레일에 취소 요청이 나갑니다. **되돌릴 수 없습니다.** |
| 실제 예약 | 늘 진짜로 보냅니다. 대신 시작할 때 확인 창이 뜨고, 로그인하지 않았으면 시작이 막힙니다. |
| 장바구니 | **부르지 않습니다.** `allow_cart=True` 를 만드는 코드가 이 폴더에 없습니다(시험이 원문으로 확인). |
| 중복 예약 | 하나 잡으면 그 자리에서 끝납니다. 재시도한 예약은 중복 예약입니다. 구간별 예약이 반만 성공해도 마찬가지로 멈춥니다. |
| 검증 안 된 환승 | 한 건으로 사지 않고 구간마다 따로 삽니다 — 서버가 `ERR911193` 로 거절하기 때문입니다. 그 대신 한쪽만 잡힐 수 있고, 그때는 멈추고 알립니다. |
| 요청 간격 | 두 겹입니다 — HTTP 훅 1.5초(화면에서 못 내림) + 조회 주기(기본 30초, 하한 10초, ±15% 흔들림). |
| 비밀번호 | 저장하지 않습니다. 설정 파일에 담을 필드가 아예 없습니다. |
| 텔레그램 토큰 | 사용자 홈의 설정 파일에 `0600` 으로 저장하고, 로그·화면 어디에도 찍지 않습니다. |

설정 파일 위치는 Windows `%APPDATA%\korail-booker\settings.json`, 그 밖에는
`~/.config/korail-booker/settings.json` 입니다. 저장소 안에는 아무것도 쓰지 않습니다.

## 할 수 없는 것

- **조회 결과에 예약 폼이 요구하는 값이 빠져 오는 열차.** 검색에는 나오는데
  그 행에 예약 폼이 요구하는 값이 없어 폼을 만들 수 없는 경우입니다. 그런 줄은
  목록에서 회색으로 표시하고 '그 밖' 칸에 `예매 불가` 라고 적으며, [담기] 를
  누르면 **어느 필드가 무슨 값으로 왔는지**를 그대로 보여 주고 담지 않습니다.
  원인을 추측해서 적지는 않습니다 — 받은 값만 보여 줍니다. 자동예매 도중에
  드러나면 그 대상만 빼고 나머지를 계속 지켜봅니다.

  수서→창원중앙 KTX-산천 387 이 이 경고에 걸린 적이 있는데, **그것은 이 경우가
  아니었습니다.** 서버는 `h_trn_clsf_cd` 를 `"0A"` 로 제대로 보냈고, 그 값을
  거절한 것은 라이브러리가 이 필드를 숫자로만 제한해 둔 탓이었습니다(APK 어디에도
  그런 제한은 없습니다). 지금은 받습니다 —
  [verification-record](../docs/verification-record.md) 의 *Correction:
  `txtTrnClsfCd` is not digits-only* 에 적어 두었습니다.
- **비회원 예매.** 라이브러리의 예약 경로가 로그인 세션을 요구하고, 폼 자체가
  회원 전용입니다(`ReservationRequest.java:105-119`). 이 프로그램이 우회할 수
  있는 것이 아닙니다.
- **입석+좌석 병합 예약(`1202`).** 두 번째 호출인 `reserve_merge` 가 실서버에
  나간 적이 없어, 반쯤 검증된 경로로 진짜 예약을 만들지 않습니다.
- **환승 예약대기.** 예약대기는 직통·일반실에만 있습니다. 라이브러리도 환승
  여정의 예약대기를 거절합니다.
- **가상대기실(NetFunnel) 대기 처리.** 명절 같은 대기열 상황은 다루지 않습니다.

## 환승 두 가지의 근거가 다릅니다

- **서버 추천 환승** — `search_transfer_trains` 가 짝지어 준 여정. 앱이 하는
  그대로이고, `reserve_transfer` 로 한 PNR 에 잡히는 것이 실서버에서
  확인됐습니다(2026-07-31 서울→오송→여수EXPO).
- **환승역 직접 지정** — 서버에 "이 역에서 갈아타는 여정을 달라"고 물을 방법이
  없어서(환승 검색 폼에 환승역 필드가 없습니다), 이 프로그램이 두 구간을 각각
  직통으로 조회해 붙입니다. 예약 폼은 만들어지지만 **서버가 이런 조합을
  받아들이는지는 확인된 바 없습니다.** 목록에서 주황색으로 표시하고, 자동예매를
  시작할 때 한 번 더 묻습니다.

## 텔레그램 알림 붙이기

값이 **둘** 필요합니다 — 봇 토큰과 대화 ID. 프로그램의 [텔레그램 설정] 창이
아래와 같은 순서로 안내하고, 각 단계의 단추가 그 자리에 있습니다.

**1단계 — 봇 만들기** (텔레그램 앱에서)

1. 검색창에 `@BotFather` (파란 체크가 붙은 것) → 대화 열기
2. `/newbot` 보내기
3. **봇 이름**을 아무거나 보내기 (예: `코레일 알림`)
4. **봇 아이디**를 보내기 — 반드시 `bot` 으로 끝나야 합니다 (예:
   `my_korail_alarm_bot`). 이미 쓰는 이름이면 다시 물어봅니다.

**2단계 — 토큰 붙여넣기**

답장에서 `Use this token to access the HTTP API:` **바로 아랫줄**을 통째로
복사해 [봇 토큰] 칸에 넣습니다. 모양은
`123456789:ABCdefGHIjklMNOpqrSTUvwxYZ` — 숫자, `:`, 긴 문자열입니다.
[토큰 확인] 을 누르면 봇 아이디를 되읽어 보여 줍니다(`getMe`). 이게 되면
토큰은 맞는 것입니다.

> 이 토큰은 **봇을 통째로 조종할 수 있는 열쇠**입니다. 화면 캡처에 찍히지
> 않게 조심하세요. 새어 나갔으면 BotFather 에서 `/revoke` 로 폐기하고 새로
> 받으면 됩니다.

**3단계 — 봇에게 먼저 말 걸기** ← 여기서 가장 많이 막힙니다

BotFather 답장 첫 줄의 `t.me/…` 링크를 눌러 **내 봇과의 대화**를 열고,
[시작] 단추를 누르거나 `/start` 를 한 번 보냅니다.

**텔레그램은 사용자가 먼저 말을 건 적이 없는 봇에게 대화 ID 를 주지
않습니다.** 이 단계를 건너뛰면 다음 단계의 [내 대화 ID 찾기] 가 늘 빈손으로
돌아옵니다 — 토큰이 틀린 것이 아닙니다.

**4~6단계 — 채우고 확인하고 저장**

[내 대화 ID 찾기] → 숫자가 채워집니다. [테스트 전송] → 봇에게 메시지가 오면 끝.
[저장].

> **대화 ID 는 숫자입니다.** `@my_korail_alarm_bot` 같은 **봇 이름을 넣는 칸이
> 아닙니다** — 텔레그램이 `@이름` 을 받는 것은 채널·슈퍼그룹뿐이고, 봇 자신은
> 대화 상대가 될 수 없습니다.
>
> [내 대화 ID 찾기] 는 **이 칸에 뭐가 적혀 있든 보지 않고 덮어씁니다.**
> 봇이 받은 마지막 메시지(`getUpdates`)의 `chat.id` 를 읽어 넣기 때문입니다.
> 그래서 무엇을 쳐 넣었든 누르는 순간 숫자로 바뀝니다 — 여러분이 3단계에서
> `/start` 를 보냈으니, 그 숫자는 **여러분 계정과 봇 사이의 대화 번호**입니다.
> 누구 것인지 헷갈리지 않게 창이 이름도 함께 보여 줍니다.
>
> 숫자가 아닌 값으로는 [테스트 전송]·[저장] 이 되지 않고 그 자리에서 말해 줍니다.

**잘 안 될 때** — 증상은 "안 와요" 하나인데 원인이 둘이라, 창이 그 둘을
갈라 줍니다.

| 무엇이 | 무슨 뜻 |
| --- | --- |
| [토큰 확인]이 실패 | 2단계. 토큰을 잘못 복사했습니다(앞뒤 공백·줄바꿈·한 글자 빠짐). |
| [토큰 확인]은 되는데 대화 ID 를 못 찾음 | 3단계를 안 했습니다. 봇 대화에서 `/start`. |
| 둘 다 채웠는데 테스트 실패 | 봇 대화를 차단했는지 보세요. |

**저장할지, 이번만 쓸지** — 창 아래 단추가 셋입니다.

| 단추 | 하는 일 |
| --- | --- |
| [⑥ 저장하고 쓰기] | 이 컴퓨터의 설정 파일에 적습니다. 다음에 켤 때도 그대로 있습니다. |
| [이번만 쓰기] | 파일에 아무것도 쓰지 않고 이번 실행에만 씁니다. 프로그램을 끄면 사라집니다. |
| [저장된 값 지우기] | 설정 파일에서 토큰과 대화 ID 를 비웁니다. |

남의 컴퓨터나 공용 컴퓨터라면 [이번만 쓰기] 쪽입니다 — 토큰은 그 봇을 통째로
조종할 수 있는 열쇠라, 디스크에 남기지 않는 편이 나을 때가 있습니다. 둘 다
있으면 **이번만 쓰기로 넣은 값이 이깁니다**(방금 넣은 쪽을 쓰겠다는 뜻이므로).

토큰은 이 컴퓨터의 설정 파일에만 `0600` 으로 저장되고, 화면·기록 어디에도
찍히지 않습니다(`mask_token` 이 예외 문구에서도 지웁니다).

### 화면은 띄워서 확인합니다

화면 쪽 시험은 전부 **소스를 읽어** 확인합니다 — 시험 환경에 tkinter 가 없어
`ui.py` 는 import 조차 되지 않기 때문입니다. 그런데 소스 확인은 "그렇게 쓰여
있다" 까지만 말해 주고, **그려 놓으니 잘리더라** 는 말해 주지 못합니다. 실제로
그렇게 [조회] 단추가 잘리고, 예매 대상의 촉박 경고가 표 밖으로 밀려나 있었던
적이 있습니다.

그래서 화면이 있는 곳에서 손으로 돌리는 확인을 따로 둡니다:

```bash
# 창을 띄워 동작을 확인하고 몇 개가 통과했는지 적습니다
xvfb-run -a --server-args="-screen 0 1600x1200x24" python3 scripts/gui_smoke.py

# 화면을 찍어 눈으로 보고 싶을 때
xvfb-run -a python3 scripts/gui_smoke.py --shot /tmp/main.png
```

네트워크를 쓰지 않고, `HOME` 을 임시 폴더로 바꿔 진짜 설정 파일도 건드리지
않습니다. 화면 배치를 바꿨으면 이것을 돌려 보세요 — 오프라인 시험은 통과하는데
단추가 잘리는 일이 실제로 있습니다.

| **감시 중인 예매 대상은 빼거나 비울 수 없음** | [빼기]는 원래도 감시 중인 열차를 막았는데, 고른 것 중 하나라도 감시 중이면 **전부** 안 빠졌습니다. 이제 감시 중이 아닌 것은 그대로 빼고, 감시 중인 것만 남긴 채 왜 안 뺐는지 알려 줍니다. [비우기]도 감시가 하나라도 돌면 통째로 막혀 있었는데, 이제 감시 중인 열차만 남기고 나머지는 비웁니다. |
| **자동예매가 하나 잡혔다고 스스로 끝내지 않음** | 서로 다른 열차 여러 편을 감시 중일 때, 그중 하나가 잡히면 **감시 전체가 끝났습니다** — 방향(출발역·도착역·날짜)이 같으면 "이 방향은 끝났다" 고 판단했기 때문입니다. 그런데 같은 방향에 서로 다른 열차를 여러 편 골라 둔 것은 "아무거나 하나" 가 아니라 "각각 잡고 싶다" 는 뜻일 수 있습니다. 이제 결판 단위를 방향이 아니라 **정확한 열차 조합**으로 세분화해서, 하나가 잡혀도 나머지 서로 다른 열차는 계속 지켜봅니다. 감시는 사람이 멈추거나, 감시 시간이 끝나거나, 되풀이해도 소용없는 실패(세션이 계속 끊김·전송이 계속 실패)를 만나야만 스스로 끝납니다. 다만 '이어서'(1구간이 같고 2구간만 다른) 후보들은 1구간을 공유하므로, 그 후보들끼리는 예전처럼 하나가 잡히면 서로 막습니다 — 안 그러면 1구간을 두 번 살 수 있습니다. |
| **여정마다(구간마다) 좌석 등급 선택** | [담기] 옆의 **[좌석 등급…] 단추를 눌러야만 뜨는 팝업**에서 고릅니다 — 직통·환승용 [일반실][특실] 한 벌과, '이어서' 전용 1구간·2구간 체크박스 두 벌입니다(처음에는 상시 노출된 체크박스 줄로 만들었는데, 화면을 찍어 보니 [담기] 아래 뜬금없이 끼어들어 오히려 어수선했습니다 — 대부분 손대지 않는 값이라 팝업으로 옮기고, 지금 값은 단추 옆 글자로만 보여 잊지 않게 했습니다). 전부 체크된 기본값(무관)에서는 아무것도 바뀌지 않습니다 — 그 여정은 지금까지처럼 감시를 시작할 때의 공통 좌석 설정을 따릅니다. 하나라도 체크를 떼면 **그 여정에만** 좌석 선택이 굳어, 나중에 다른 좌석 콤보박스를 바꿔도 이미 담긴 그 여정은 영향받지 않습니다. '이어서'는 구간마다 따로 사므로(별개의 예약) 구간마다 독립적으로 고를 수 있지만, 직통·서버 추천 환승은 한 PNR 로 같이 사기 때문에 두 구간에 같은 등급만 적용됩니다(라이브러리 자체의 제약이자, 서버에서 실제로 확인된 것도 이 경우뿐입니다). 예매 대상 목록의 "상태" 칸에 굳힌 선택이 보이고, 실제로 어떤 등급으로 잡혔는지는 잡은 예약의 "종류" 칸과 알림에 나타납니다. **가격을 합산해 보여 주지는 않습니다** — 열차 조회 응답에는 예약 전 운임을 구조화된 숫자로 주는 필드가 없고(서버 문구 안에 섞여 오는 경우만 있음), 그 문구를 파싱해 억지로 합산하면 틀린 금액을 보여줄 위험이 있어 만들지 않았습니다. |

| **창을 닫아도 자동예매가 백그라운드에서 계속됩니다(윈도우 전용)** | 창의 X 단추를 누르면(트레이가 켜졌을 때만) 창을 숨기기만 하고, 안내 팝업을 띄웁니다("완전히 끄려면 트레이 아이콘에서 [종료]"). 작업 표시줄 오른쪽 아래에 뜨는 트레이 아이콘을 우클릭하면 [뉴레일 열기]·감시 상태("▶ N편 감시 중")·잡은 예약 건수·[전체 중지]·[서버에서 예약 다시 불러오기]·[종료] 가 뜹니다. 왼쪽 클릭(또는 더블클릭)은 곧장 창을 되살립니다. **[종료] 를 눌렀을 때만** 지금까지 창을 닫을 때 쓰던 경고(예약 요청이 나가 있음 / 자동예매가 도는 중 / 결제 기한이 남은 예약이 있음)가 그대로 나갑니다 — 창을 숨길 때는 나가지 않습니다. |
| **왜 윈도우 전용인가** | 트레이 아이콘은 `pystray` 라이브러리를 쓰는데, 그 소스를 직접 읽어 백엔드 셋의 신뢰도가 서로 다름을 확인했습니다. **win32**: 진짜 스레드를 새로 만들어 도는, 이 프로그램의 스레드 규칙과 잘 맞는 구현입니다. **xorg(Linux)**: 트레이 매니저가 없는 컴퓨터에서 **예외 하나 없이 조용히 실패**합니다 — 직접 Xvfb 로 띄워 확인했습니다(아이콘이 안 보이는데 `icon.visible` 은 그래도 `True`). 창을 숨겼는데 트레이가 안 보이면 되찾을 길이 없어지므로 위험합니다. **darwin(macOS)**: `run_detached()` 문서 자신이 `NSApplication` 과 직접 엮으라고 하는데, 이 프로그램은 순수 Tkinter라 그 엮음이 없어 사실상 아무 것도 돌지 않습니다. 그래서 `pystray`/`pillow` 자체는 윈도우가 아니어도 설치될 수 있지만(설치기가 막지 않습니다), 트레이 기능은 `sys.platform == "win32"` 일 때만 켭니다 — 다른 곳에서는 창을 닫으면 지금까지처럼 곧장 끝납니다. |
| **트레이가 없어도(또는 못 만들어도) 프로그램은 그대로 돕니다** | `pystray`/`pillow` 설치 자체가 안 됐거나, 트레이 아이콘을 만들다 무엇이든 실패하면 조용히 넘어가고 — 창의 X 단추는 지금까지처럼 곧장 끝내는 동작으로 돌아갑니다. 실행기(`실행 (Windows).bat`)도 이 둘의 설치 실패로 멈추지 않습니다. |

⚠️ **이 트레이 기능은 실제 Windows 에서 확인하지 못했습니다** — 개발 환경이
Linux 라, `pystray` 의 win32 백엔드 코드를 읽고(진짜 스레드를 새로 만들어
도는 것, `MenuItem` 의 동적 문구·활성/비활성이 실제로 지원되는 것 등을
소스로 확인) 그 계약에 맞춰 짰을 뿐, 실제 Windows 작업 표시줄에 아이콘이
뜨고 우클릭 메뉴가 제대로 나오는지는 실사용으로 아직 확인하지 못했습니다.
이상하게 보이거나 안 뜨면 알려 주세요 — 운행 일정 기능처럼, 실사용 확인이
되면 이 경고를 뗄 수 있습니다.

## 트레이 실사용 확인에서 고친 것 (10차 후속)

바로 위 트레이 기능을 실제로 써 보신 뒤 신고받은 것 둘입니다.

| 무엇이 잘못됐었나 | 왜, 어떻게 고쳤나 |
| --- | --- |
| **창을 닫으면 트레이로 안 가고 곧장 종료 경고가 떴다** | `실행 (Windows).bat` 이 `pystray`/`pillow` 를 **`.venv` 가 이미 있으면 건너뛰는 "처음 한 번만" 준비 단계 안에서만** 설치하고 있었습니다 — 이 세션 내내 그래왔듯, 한 번 만들어 둔 `.venv` 를 계속 쓰는 사람은 이 기능이 생긴 뒤에도 이 둘을 받을 기회가 없어 트레이 아이콘이 늘 `None` 이었고, `on_close` 는(스스로는 옳게) 트레이 없음으로 판단해 곧장 진짜 종료로 갔습니다 — 버그가 아니라 애초에 트레이가 못 켜진 것이었습니다. `실행 (Windows).bat` 을 고쳐, `.venv` 가 이미 있어도 매번 `python -c "import pystray"` 로 **로컬에서만** 있는지 먼저 보고(인터넷을 쓰지 않아 빠릅니다), 없을 때만 그 자리에서 한 번 채워 넣게 했습니다. `exe 만들기 (Windows).bat` 도 같은 문제가 있어(빌드용 `.venv` 가 이미 있으면 건너뜀), pystray 설치를 **항상 도는 자리**(PyInstaller 준비 단계)로 옮겼습니다 — **이미 만들어 둔 exe 는 이 고침이 반영 안 된 채로 빌드된 것이라, `exe 만들기 (Windows).bat` 을 다시 돌려야** 트레이가 켜집니다. |
| **종료 경고 문구가 지저분했다** | 결제 기한을 모르는 예약(서버에서 불러온 것)이 여럿이면, 그 각각에 긴 문구("서버가 이 목록에서 결제 기한을 주지 않습니다 — 코레일 앱에서 확인하세요")가 줄마다 그대로 반복돼, 정작 기한을 아는 예약이 묻혔습니다. 기한을 아는 것은 지금처럼 "PNR  언제까지" 로 짧게, 모르는 것은 "그 밖에 결제 기한을 알 수 없는 예약 N건" 한 줄로만 묶었습니다. |

| **"소리가 안 난다" 는 신고를 따라간 재생 방식 변경** | 예전에는 Windows 에서 `winsound.PlaySound` 에 WAV 바이트를 메모리로 바로 넘겼는데(`SND_MEMORY`), 실사용에서 전혀 소리가 안 난다는 신고가 있었습니다. 이 사설망 환경에서는 직접 재현해 원인을 확정할 수 없었지만, 더 널리 쓰이고 더 잘 검증된 방식인 **임시 파일에 저장한 뒤 파일 경로로 재생**(`SND_FILENAME`)으로 바꿨습니다 — macOS·Linux 는 원래도 파일 방식이었으므로 세 플랫폼이 이제 같은 방식을 씁니다. |
| **알림 설정을 한데 모음** | "텔레그램 알림"·"예약 성공 종소리" 체크박스와 "텔레그램 설정"·"종소리 미리듣기" 단추가 조회 주기·감시 시간과 한 줄에 뒤섞여 있었습니다. "알림" 이라는 이름의 묶음으로 따로 빼, 텔레그램 줄과 알림소리 줄을 나눠 담았습니다. |

## 창은 한 번에 하나만 (17차)

트레이에 숨겨 둔 채 잊고 exe 를 다시 누르면 창이 하나 더 늘어, 자동예매
감시도 예약도 따로 도는 문제가 있었습니다.

| 무엇 | 어떻게 |
| --- | --- |
| **exe 를 다시 실행하면 새 창 대신, 있던 창을 앞으로** | `korail_booker/single_instance.py` 를 새로 뒀습니다 — 127.0.0.1 로만 열리는 TCP 소켓 하나로 "이 컴퓨터에서 뉴레일은 하나만" 을 표시합니다. 첫 실행이 정해 둔 포트를 잡아 원본이 되고, 이미 원본이 있으면(그 포트가 잡혀 있으면) 둘째는 그 포트로 신호만 보내고 **창을 아예 열지 않고** 곧장 끝납니다. 원본은 신호를 받으면 트레이의 [뉴레일 열기] 와 같은 동작(`_restore_from_tray`)으로 창을 앞으로 불러옵니다. 실제로 `run()` 을 두 번 띄워 확인했습니다 — 둘째는 0.3초 만에 끝나고, 창은 하나만 남습니다. |

## 텔레그램 설정 창을 값 입력과 설명으로 나눔 (18차)

16차 판을 실제로 켜 보시고 "사진이 하나도 안 보인다" 는 지적을 주셨습니다.
캡처 사진 세 장을 [텔레그램 설정] 창 하나에 욱여넣으려니, 그 창이 이미
토큰·대화 ID 칸에 4단계 설명까지 담고 있어 사진을 가로 230px(2번 사진은
85px!)까지 줄여야 했습니다 — 그 크기면 사진이 있어도 안 보이는 것이나
다름없습니다. 화면을 직접 Xvfb 로 찍어 실측해 보니 정말 그 정도로 작게
찍혀 있었습니다.

| 무엇 | 어떻게 |
| --- | --- |
| **[텔레그램 설정] 은 값만, [설정법 보기] 는 사진 설명만** | 메인 화면의 "텔레그램 설정" 단추 옆에 **[설정법 보기]** 단추를 새로 뒀습니다. [텔레그램 설정] 창에서는 1~4단계의 긴 설명과 사진을 모두 빼고 토큰·대화 ID 입력칸, [토큰 확인]·[내 대화 ID 찾기]·[테스트 전송]·[저장하고 쓰기] 등 단추만 남겼습니다 — 어떻게 그 값을 얻는지는 "설정법 보기 2단계를 다시 보세요" 처럼 짧게 안내하고, [설정법 보기] 를 누르면 별도 창에서 1~4단계 설명과 사진을 봅니다. |
| **사진이 실제로 읽을 수 있는 크기로** | 분리한 덕에 사진을 더는 억지로 줄이지 않아도 됩니다 — BotFather 검색 화면은 절반(459×58), 토큰·대화 시작 화면 두 장은 원본 그대로(424×685, 424×686)로 보여 줍니다. [설정법 보기] 창도 사진까지 곁들이면 화면 높이를 넘기므로 [텔레그램 설정] 과 같은 방식으로 세로 스크롤을 달았습니다. |
| **exe 빌드가 새 그림 폴더 때문에 실패하던 것도 같이 고침** | 지난 16차에서 `--add-data` 를 추가했는데, 상대 경로(`app\assets;assets`)로 넣어 뒀던 탓에 `exe 만들기 (Windows).bat` 을 실제로 돌리자 `ERROR: Unable to find '...\build\app\assets'` 로 빌드 자체가 실패했습니다 — `--specpath` 를 CWD 와 다르게(`build\`) 두는 이 배치 파일의 특성상 상대 경로가 workpath 기준으로 다시 풀리는, 아이콘 경로와 똑같은 함정이었습니다. 아이콘처럼 `%CD%` 를 붙여 절대 경로로 고쳤습니다. **이미 만들어 둔 exe 를 쓰고 계시다면(또는 위 오류로 실패했다면) `exe 만들기 (Windows).bat` 을 다시 돌리셔야 합니다.** |

## 감사에서 고친 것들

프로그램 전체를 한 줄씩 훑는 감사를 돌렸습니다 — 파일·구간마다 읽는 사람을
따로 두고, 스레드 안전성·위젯 수명·상태 일관성·시간/자정·라이브러리 계약·금전
안전성을 횡단으로 한 번 더 본 뒤, 나온 지적마다 관점이 다른 회의론자 셋이
"그 코드가 정말 그런가 / 도달 가능한가 / 그 수정이 다른 것을 깨지 않는가" 를
따로 판정하게 했습니다. 고친 것 중 사람에게 손해가 갈 수 있었던 것들:

| 무엇이 | 어떻게 됐었나 |
| --- | --- |
| 결제 기한 시각 | 서버가 09:30 을 숫자 `93000` 으로 보내면 `93:00:0` 이라는 없는 시각이 알림과 목록에 찍히고, 카운트다운은 같은 값을 거절해 `기한 모름` 이라고 적었습니다. 두 곳이 어긋나 **진짜 기한을 알 방법이 없었습니다.** 이제 앞의 0 을 되살려 둘이 같은 값을 씁니다. |
| 카운트다운 기준 시각 | 서버가 주는 기한은 **한국 시각**인데 컴퓨터의 지역 시계와 그냥 뺐습니다. 시간대가 다른 노트북에서 남은 시간이 몇 시간씩 틀렸습니다. 이제 KST(UTC+9, 서머타임 없음)로 잽니다. |
| 잡아 둔 예약 | 감시가 시간 끝·중지·실패로 끝나면 결과에 홀드가 하나도 실리지 않았습니다. 왕복에서 가는 편을 잡아 둔 채 오는 편이 시간 끝을 만나면 **그 예약의 PNR 과 기한이 통째로 사라졌습니다.** 이제 어느 갈래로 끝나든 실립니다. |
| 예약 요청이 끊길 때 | 전송 실패가 잡히지 않아 감시가 그 자리에서 죽었습니다 — 서버에 예약이 생겼는지 모른 채. 이제 멈추고 크게 알립니다. **다시 보내지 않습니다**(이미 생겼다면 중복 예약이 됩니다). |
| 한 방향, 두 예약 | 같은 방향에 감시를 두 묶음 걸 수 있었고, [바로 예약] 은 도는 감시를 보지 않았습니다. 엔진은 한 묶음 안에서만 "방향마다 하나" 를 지키므로 **진짜 예약이 두 번 나갔습니다.** 이제 감시 중이거나 이미 잡힌 방향은 막습니다. |
| 여정 열쇠 | 날짜가 빠져 있어 같은 열차의 다른 날짜가 서로 같은 것으로 취급됐습니다. 둘째 감시가 조용히 안 걸리고, 폼을 못 만들어 뺀 열차는 다른 날짜까지 함께 빠졌습니다. |
| 예매 대상 선택 | 표를 다시 그릴 때마다 선택이 사라졌습니다(옛 항목 id 로 찾았습니다). [고른 것만 시작]·[고른 것만 중지]·[조건 바꿔 재시작] 이 **조용히 '전부' 가 됐습니다.** |
| 요청 간격 | 1.5초 바닥을 지키는 `Pacer` 에 잠금이 없어, 감시 스레드가 여럿이면 같은 순간에 한꺼번에 쐈습니다. 그 바닥은 IP 차단을 피하려고 있는 것입니다. |
| 설정 파일 | 제자리에 덮어써서 쓰다가 멈추면 토큰까지 함께 잃었고, umask 권한으로 만든 뒤에야 `0600` 으로 좁혔습니다. 이제 옆에 만들어(처음부터 소유자 전용) 마지막에 갈아 끼웁니다. |
| 텔레그램 | `httpx.InvalidURL` 은 `HTTPError` 가 아니라, 토큰에 줄바꿈이 하나 끼면 그것이 새어 나가 **그날 밤 알림이 통째로 사라졌습니다.** [내 대화 ID 찾기] 는 밀린 메시지가 많으면 **가장 오래된** 대화의 번호를 넣었습니다(이제 `offset=-1`). |
| 휠 스크롤 | 창을 굴리려던 휠이 좌석 등급·출발역·시각 콤보박스의 값을 조용히 바꾸고, 바뀐 값은 그대로 화면 밖으로 밀려났습니다. |
| 겹친 조회 | Enter 는 잠긴 [조회] 단추를 그냥 지나가서 조회가 겹쳐 돌았고, 먼저 시작한 쪽이 늦게 끝나면 **옛 결과가 새 결과를 덮었습니다** — 표는 초록으로 "지금 조건의 결과" 라고 말하면서. |
| 자정을 넘기는 환승 | 1구간이 자정을 넘겨 도착하면 2구간은 **다음 날** 것이어야 하는데, 오늘 날짜로 조회한 열차를 붙여 "몇 시간 뒤 환승" 으로 내놓았습니다. 이제 그런 조합은 뺍니다. |
| 자동예매의 전송 실패 | 조회 갈래가 전송 실패를 삼켜, "연속 실패 다섯 번이면 멈춤" 이 영영 동작하지 않았습니다. 인터넷이 끊긴 밤새 `고른 열차가 조회 결과에 없습니다` 만 찍혔습니다. |
| 끝났다는 알림 | 감시 고리에서 예외가 새면 "반드시 알린다" 던 종료 알림이 건너뛰어졌습니다. 밤새 켜 둔 사람은 시작 알림만 받고 아무 소식도 못 받았습니다. |
| 창 닫기 | 예약 요청이 나가 있어도, 결제 기한이 남은 예약 목록이 있어도 아무 말 없이 닫혔습니다(목록은 메모리에만 있습니다). 이제 묻습니다. |

그다음 **실행 기반 2차 감사**를 돌렸습니다 — 읽는 대신 Xvfb 에서 창을 몰아
보고, MockTransport 로 엔진을 돌리고, 입력을 공격하고, 앞의 수정들 자체를
적으로 보고 감사하게 했습니다. 거기서 또 나온 것들:

| 무엇이 | 어떻게 됐었나 |
| --- | --- |
| 기한을 읽는 곳이 둘 | 화면 글과 카운트다운이 따로 읽어, 네 자리로 온 시각 하나가 한쪽에서 00:16 이고 다른 쪽에서 16:00 이었습니다 — **두 칸이 12시간 다른 기한**을 말한 셈입니다. 이제 해석은 `holds.parse_deadline` 한 곳뿐이고 화면 글도 그것을 거칩니다. |
| 끊긴 예약이 "미리보기" 로 끝남 | 전송이 끊긴 뒤 마지막 방향이면 결과가 `PREVIEW` — "아무것도 보내지 않았습니다" 였습니다. **진짜로 보냈는데** 그렇게 끝나면 사람은 안 생긴 줄 알고 기한을 넘깁니다. |
| 예약대기 전송 실패 | 예약대기 POST 의 세션 만료·전송 실패를 아무도 안 잡아 감시가 통째로 죽었고, 다시 로그인은 한 번도 시도되지 않았습니다. |
| 다시 로그인 자체의 실패 | 비밀번호가 바뀌었으면 예외가 그대로 새어 감시가 첫 회차에 죽었습니다 — 남은 횟수도 전송 실패 카운터도 소용없이. |
| 방향 잠금의 구멍 | "이 방향은 이미 잡았다" 를 **예매 대상 목록에 그 줄이 남아 있을 때만** 판단했습니다. 줄을 빼면 근거가 사라져 같은 구간에 두 번째 예약이 나갔고, [바로 예약] 이 답을 기다리는 몇 초 사이에 감시를 걸면 같은 열차를 두 번 잡았습니다. 이제 예약과 감시가 **스스로 방향을 들고 다닙니다.** |
| [바로 예약] 의 끊김 | 전송 끊김도 그냥 "실패" 로 적어, 사람이 다시 눌러 중복 예약을 만들 수 있었습니다. |
| 반만 산 환승 | 앞 구간만 잡혔는데 잡은 예약 목록에는 **여정 전체**를 산 것처럼 적혔습니다. |
| 휠이 값을 바꿈 | 역 칸만 막혀 있었고, 정작 주석이 예로 든 좌석 등급 칸과 시각 칸은 그대로 굴러갔습니다. |
| '오늘' 의 기준 | 지난 날짜 판정과 달력이 노트북 시계를 써서, 한국에서는 아직 오늘인 날짜를 거절했습니다. |
| 감시 끝 알림 | `_drain` 안에서 모달을 열어 [확인] 을 누를 때까지 화면 갱신이 멈췄습니다(도는 감시의 기록도 카운트다운도 함께). |
| 선택 되돌리기 | 줄 번호로 되돌려서, [빼기] 로 앞줄이 사라지면 **고른 적 없는 열차**가 골라졌습니다. |
| 환승 예산 | 사용자의 환승시간 조건에 걸릴 조합이 40편 예산을 다 먹어, 조건에 맞는 조합이 화면에 안 나왔습니다. |

전부 회귀 시험을 함께 붙였습니다. 다만 **어느 것도 실서버로 확인한 것이
아닙니다** — 검증은 MockTransport 와 Xvfb 까지입니다.

## 이것도 매크로입니다

본인 계정으로, 본인이 탈 표를 기다리는 데 쓰라고 만든 것입니다. KORAIL 은
매크로성 트래픽에 IP 를 막고, 서버가 이 트래픽을 어떻게 볼지는 KORAIL 이
정합니다. 주기를 낮추지 마세요.
